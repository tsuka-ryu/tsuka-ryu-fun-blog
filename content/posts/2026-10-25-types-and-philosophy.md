## お断り

最初に断っておくと、自分は型システムの専門家でもなければ、哲学の専門家でもない。どっちも独学で、気になったところをつまみ食いしてきただけ。なのでこれは正確な解説ではなく、素人が自分の関心を無理やりつなげてみた記録くらいに思ってほしい。

あと、この記事はClaudeと壁打ちしながら考えたことをまとめている。なので事実関係や解釈が怪しいところもあるかもしれない。気になったら原典や専門書をあたってほしいし、間違いがあれば教えてもらえるとうれしい。

## はじめに

最近、Leanを触り始めた。けど何もわからなかったので、まず論理学を勉強し始めた。ついでに、前からなんかかっこよさそうだと思っていたウィトゲンシュタインにも手を出した。

もともと哲学には興味があって、ショーペンハウアーはなんとなく好きだし、初期仏教も好きだ。最近はフランス現代思想にも惹かれている。どれも体系立てて学んだわけではなく、ただ気になって読んできただけ。

一方、プログラミングの側ではHaskellやTypeScript、Rustの型システムが気になっている。

これらはずっと別々の関心だと思っていた。けど東京大学出版会の『論理学』を読んでいたら、ラッセルの型理論が出てきて、プログラミングの型システムの源流がここにあると知った。そこから、ずっと引っかかっていることがある。ウィトゲンシュタインの『論理哲学論考』でいう語りえないものって、型で表現できないもの、つまり論理空間に所属できないものでしかないんじゃないか。

そう考えると、哲学の側からプログラミングを解釈できる気がしてくる。だったら逆に、プログラミングの側からも哲学を読めるんじゃないか。HaskellやRust、TypeScriptの考え方を道具にして哲学を読んでみる、というのがこの記事でやりたいことだ。

ということで、カントとショーペンハウアーから、カントール、フレーゲ、ラッセル、ブラウワー、ウィトゲンシュタイン、ゲーデル、西田幾多郎を経て、その先の東浩紀やニーチェ、ナーガールジュナまで、雑に読んでみる。

## カント：認識はパースである

カントは、認識をZodのパースみたいなものとして描いた最初の人だと言えそうだ。自分たちは物自体を直接見ることはできない。物自体は `unknown` な入力で、認識はそれをスキーマに通して、扱える値にする処理だ。

スキーマは二段になっている。時間と空間は入力フォーマットで、どんなものも「いつ、どこ」という形でしか入ってこない。カテゴリーのほうは、因果とか実体とかで、型クラスにかなり近い。経験に出てくるものは全部、因果の制約を満たすインスタンスとして扱われる。

```ts
const thingInItself: unknown = reality; // 物自体：中身に触れられない
const phenomenon = Experience.parse(thingInItself); // 現象：スキーマを通った値
```

パースを通る前の `unknown` には何もできない。カントにとって、パースできるのは経験の範囲だけだった。

じゃあ経験の外にあるものまで無理やりパースしようとするとどうなるか。世界は有限か無限か、と問うと、有限だという論証も無限だという論証も、どっちももっともらしく組めてしまう。カントはこういう矛盾を四つ挙げて、アンチノミーと呼んだ。つまり経験の外にあるものは、そもそもパースする意味がない。無理にパースしても、出てくるのは矛盾だけだ。この構図は、あとで出てくるラッセルのパラドックスとほとんど同じ形をしている。

もう一つ覚えておきたいのが、カントが数学を「総合的アプリオリ」だと考えたことだ。たとえば 7 + 5 = 12 は、経験しなくてもわかる。かといって、7という概念と5という概念をいくら分析しても、12は出てこない。実際には、7に1を一つずつ5回足していく、つまり時間の中で順に数え上げて初めて12にたどり着く。だから算術は、ただの論理の言い換えではなく、時間の直観に支えられている、というのがカントの主張だ。

プログラミングで言うと、自然数をゼロと「次の数」で定義して、再帰で一歩ずつ計算していく感覚に近い。

```haskell
data Nat = Zero | Succ Nat

add :: Nat -> Nat -> Nat
add n Zero     = n
add n (Succ m) = Succ (add n m)  -- 一歩ずつ数え上げる
```

## ショーペンハウアー：REPLの中から触る

ショーペンハウアーは、自分こそカントの正統な後継者だと思っていた人だ。カントが「わからない」とした物自体に、別の道から触ろうとする。

外からパースを通して見る限り、物自体はわからない。けど自分たちは、自分の身体を内側から生きている。そこで直接感じられるものこそ物自体で、その正体は盲目的な「意志」だ、と彼は言う。

プログラミングで言うと、カントはパース済みの値だけを見ていた。ショーペンハウアーは、REPLで動いているLispのイメージに近い。コンパイルと実行の区別がなくて、走っているシステムの中に自分も入って、いじりながら動かしている。外から眺めるんじゃなく、動いているものの中から直接触っている、という感じだ。しかもその動きには目的がない。ただ欲し続けて、満たされず、また欲する。だから生は苦しい。この結論が仏教っぽいのは、本人も認めていた。

面白いのは、彼が数学でも直観を重視していたことだ。ユークリッドの証明を、見ればわかることを回りくどく論証している、と批判している。証明より直観、という人だった。

## カントール：対角線という通奏低音

カントールは、無限にも大小があることを示した。自然数の集合より、実数の集合のほうが真に大きい。その証明に使われたのが対角線論法だ。

仕組みは単純で、実数を全部並べたリストがあるとする。n番目の数のn桁目を全部ずらした数を作ると、その数はリストのどの数とも少なくとも一桁違う。つまり、どんなリストにも載らない数が必ず作れてしまう。

「自分自身と食い違うものを作る」。この技法が、この記事の通奏低音になる。ラッセルのパラドックスも、ゲーデルの不完全性定理も、チューリングの停止性問題も、仕組みは全部この対角線だ。何かを全部扱おうとする体系が自分自身まで扱おうとすると、必ず扱いきれないものが出てくる。この記事の後半は、ずっとこれの変奏になる。

## フレーゲ：論理だけで算術を作る夢

フレーゲはカントに反論した。7 + 5 = 12 を言うのに、時間の中で数え上げる直観なんていらない。算術は論理だけから作れるはずだ、と。

そのために彼は、1879年の『概念記法』で、いまで言う命題論理と述語論理をほぼゼロから作ってしまった。「かつ」「ならば」「でない」で文を組み立てるのが命題論理で、そこに「すべての x について」「ある x が存在して」という量化子を足したのが述語論理だ。大学の論理学の授業で最初に習うあれは、だいたいフレーゲが作ったものらしい。

ちなみにカントは『純粋理性批判』で、論理学はアリストテレス以来一歩も進んでいないし退いてもいない、完成した学問だと書いている。その2000年以上止まっていた論理学を、カントの約100年後に一気に更新したのがフレーゲだった。そしてこの論理の上に、数の定義から算術全体を組み上げようとした。

ところが1902年、第二巻の刊行直前に、若いラッセルから一通の手紙が届く。その体系からは矛盾が導けますよ、という指摘だった。

## ラッセル：型の誕生

いきなり集合の話になるけど、これはフレーゲの論理とちゃんとつながっている。フレーゲの体系では、述語、たとえば「x は偶数である」があれば、それを満たすものを全部集めた集合（偶数の集合）が必ず作れることになっていた。述語ひとつにつき集合ひとつ。論理で数を作るには、この対応がどうしても必要だった。で、この「どんな述語からでも集合が作れる」というルールが、穴になっていた。

ラッセルのパラドックスは、カントールの対角線を集合に向けたものだ。

「自分自身を要素に含まない集合」を全部集めた集合 R を考える。R は自分を含むか。含むなら定義により含まないし、含まないなら定義により含む。

ラッセルの解決策が型理論だった。対象、対象の集合、集合の集合、と階層を分けて、集合は自分より下の階層のものしか要素にできないことにする。

```haskell
-- イメージ：階層を越えた自己言及を型で禁じる
data Level0 = Individual
newtype Level1 = SetOf [Level0]
newtype Level2 = SetOfSets [Level1]
-- Level1 が Level1 を要素に持つことは書けない
```

ここで強調しておきたいのは、型はもともと比喩じゃなく、自己言及を禁じる装置として発明されたということだ。プログラミング言語の型は、この系譜の直系の子孫なんだと思うと、ちょっとテンションが上がる。

ただ、これで全部解決したわけじゃない。まず、階層は上にいくらでも続いて終わりがない。しかも「すべての集合について」と言おうとすると、それはどの階層にも収まらないので、さらに上の階層が要る。その上について語るには、またその上が要る。無限後退だ。それに、型で階層を分けると普通の数学がうまく書けなくなる。そこでラッセルは、ホワイトヘッドとの『プリンキピア・マテマティカ』で、還元公理や無限公理といった追加の公理を足した。けどこれらは論理から出てくるものじゃなく、数学を回すために後から足したパッチに近い。論理だけで数学を作るというフレーゲの夢は、ここで半分崩れている。

そしてこの『プリンキピア』こそ、のちにゲーデルが狙い撃ちにする体系だ。1931年の不完全性定理の論文のタイトルは「『プリンキピア・マテマティカ』およびその関連体系における形式的に決定不能な命題について」。型で自己言及を禁じたはずの体系の中に、ゲーデルは別の形で自己言及を持ち込むことになる。

## ブラウワー：作ってみせろ

ラッセルが論理で数学を立て直そうとしていた頃、まったく逆の方向から数学をやり直そうとした人がいる。ブラウワーだ。

ブラウワーは、カントと同じように、数学の土台は時間の中で一歩ずつ積み上げていく直観にあると考えた。ショーペンハウアーの「証明より直観」とも近い。数学は論理から出てくるんじゃなく、頭の中で実際に作り上げていくものだ、と。

そこから、かなり過激な主張が出てくる。「AかAでないかのどちらかが必ず成り立つ」という排中律を、無限については認めない。たとえば「条件を満たす数が存在する」と言いたいなら、「存在しないと仮定すると矛盾する」では足りない。その数を実際に作ってみせろ、ということだ。これが直観主義と呼ばれる立場だ。

当時は変わり者の主張だったけど、これがプログラミングと深くつながっていたらしい。直観主義の論理では、証明はそのままプログラムになり、「存在する」の証明は、その値を実際に返す関数になる。HaskellやLeanの型の世界は、この見方の上に立っているそうだ。最初に触ったときにわからなかったのは、たぶんこのあたりの感覚がなかったからなんだと思う。

## 前期ウィトゲンシュタイン：健全な型システムとその代償

### 写像理論：命題は世界の型

まず言葉の確認から。命題というのは、ざっくり言うと真か偽かが決まる文のことだ。「雪は白い」は命題だけど、「窓を閉めて」や「こんにちは」は命題じゃない。フレーゲの章で出てきた命題論理は、この命題を「かつ」「ならば」でつないで扱う論理だった。

『論理哲学論考』の構造は、まず論理空間から始まる。「猫がマットの上にいる」「雨が降っている」みたいな、成り立つか成り立たないかのどちらかになる小さな事実がたくさんあって、そのありうる組み合わせを全部並べたものが論理空間だ。

世界は、その論理空間の中で実際に成り立っている一つの組み合わせのことだ。論理空間がありうる世界の全部で、現実の世界はその中の一点、という関係になっている。

命題は、その空間のどこに現実の世界がいるかを言い当てる絵だ。「猫がマットの上にいる」という文は、猫とマットの並び方を写した絵になっていて、現実がその絵の通りなら真、違えば偽になる。だから命題は真か偽かが決まる。

プログラミングで言うと、型とデータの関係に近い。論理空間は型が許すすべての値で、世界はいま実際にある一つの値。命題は、その値がどれかを判定する関数みたいなものだと思う。

```ts
// 要素命題は独立した真偽の組
type World = { p: boolean; q: boolean; r: boolean };
// 論理空間：可能な World 全体
// 命題：論理空間のうち、どの世界で真になるかを切り出すもの
type Proposition = (w: World) => boolean;
```

ここまでをまとめると、世界は全部命題で写し取れる、つまり言葉で書ききれる、ということになる。論考は、論理的にちゃんと整った理想の記号言語があれば、世界のすべての事実をそれで書けると考えていた。だから論考では、世界と言葉はぴったり重なる。「私の言語の限界が、私の世界の限界を意味する」という有名な一文は、この図式から出てくる。

### 言うことと示すこと：メソッド呼び出しが所属を示す

さっき、命題は世界の絵だと書いた。「猫がマットの上にいる」という絵は、猫とマットの並び方を描ける。けど、「この絵はこういうふうに世界を写している」ということ自体は、絵の中に描けない。絵と世界がどう対応しているかは、絵を見れば自然とわかるだけだ。ウィトゲンシュタインはこれを、語ることはできず、示されるだけだと言った。これが論考の中心にある「言うこと」と「示すこと」の区別だ。

プログラミングだと、Haskellの型クラスがわかりやすい。

```haskell
-- 型注釈を書かなくても
same x y = x == y
-- GHC は same :: Eq a => a -> a -> Bool と推論する
```

この関数のどこにも「a は Eq のインスタンスである」とは書いていない。けど `==` を呼び出しているという事実そのものが、a がその型クラスに属していなければならないことを示している。メソッドを呼ぶことが、型クラスへの所属を語らずに示している、という感じだ。

ここでラッセルの型理論への批判が出てくる。関数が自分自身を引数にできないことは、規則として言われるべきじゃない。ちゃんと作られた記号法なら、そもそもそういう式は書けない。それが示されれば十分だ、と。

ラッセルは型の規則を言語の中に書き込もうとした。けど、ラッセルの章で見たように、規則について語るにはまた一つ上の階層が要って、その上について語るにはさらに上が要る。無限後退で、書ききることができない。ウィトゲンシュタインに言わせれば、それは示されるしかないものを語ろうとしたからだ、ということになる。

### 語りえぬもの：ドメインモデルに落ちないもの

倫理、美、生の意味は、論理空間のどこにもない。世界の中の事実じゃないからだ。けどウィトゲンシュタインにとって、それらは無意味どころか一番大事なものだった。

プログラミング言語も、結局は言語だ。世界と言葉が重なるなら、コードで書けるものの限界は、そのプログラムにとっての世界の限界になる。ドメインモデリングをしていると、これを実感する。業務を型やエンティティに落としていくと、どうしてもモデルに乗らないものが残る。なんでこの業務をやっているのか、何が大事なのか、みたいなものだ。それはモデルのどこにも書かれていないけど、モデル全体の形を決めている。

コードを書いていると、すべてをコードに書けるわけじゃないんだよな、と感じる瞬間がある。語りえぬものの話は、あの感覚にかなり一致している気がする。

モデルに乗らずに残るものを、さっきは「なんでこの業務をやっているのか、何が大事なのか」と書いた。もう少し突き詰めると、残っているのは業務そのものなんじゃないかと思う。規則は型やエンティティに書ける。けど、その規則が現場でどう適用されるかは、規則自体には書けない。

```ts
type Order = { total: number; isVip: boolean };
const freeShipping = (o: Order) => o.total >= 5000 || o.isVip;
// 「この注文は事情があるから送料無料にすべきか」は、どこにも書かれていない
```

ドメインエキスパートは、ルールを言葉にしてほしいと頼まれると詰まるのに、目の前のケースでは迷わず正しく判断する。仕様を聞き出す側が困るのは、だいたいここだ。

これは論考の語りえぬものというより、後期ウィトゲンシュタインの「規則に従うことは実践である」とか「生活形式」とかに近いらしい。まだ概念名くらいしか知らないけど、規則の意味は規則をもう一つ足しても固定できず、それを使っている人たちの実践が支えている、という方向の話だと理解している。モデルに意味を与えているのは業務そのものなのに、業務そのものはモデルの中に現れない。

論考の立場だと、業務は「モデルの外にある語れない一点」に見える。でも後期の見方だと、業務はモデルを使う人たちの振る舞いのあちこちに散らばっている。この対比は、記事の後半で東浩紀の郵便を使ってやる「一点か、散らばった穴か」を先取りしている気がする。

前期では穴に見えていたものが、後期では穴ではなく地面だったのかもしれない。モデルの外に押し出された何かではなく、モデルを立たせている足場のほうだ、と。ちゃんと読んでから、別の記事で書きたい。

### 主体：型検査器は世界の中にいない

もう一つ面白いのが、論考での主体の扱いだ。世界を見ている主体はどこにいるのか。論考は、主体は世界に属さず、世界の限界だと言う。眼が視野の中に見えないように、主体は世界の中のどこにも見つからない。

型検査器も、プログラムの中の値にはならない。プログラムのどこを探しても検査器は出てこないけど、何が書けて何が書けないかを決めているのはそれだ。

論考はさらに、独我論を徹底すると実在論と一致すると言う。独我論は「世界は私の世界だ」という立場だけど、その「私」を探しても世界の中には見つからない。主体は広がりのない一点に縮んで、残るのは世界だけになる。結局「世界がある」としか言えなくなって、普通の実在論と見分けがつかなくなる。

このあたりは、ショーペンハウアーにかなり似ている。若いウィトゲンシュタインはショーペンハウアーを読み込んでいて、「世界は私の表象である」から出発しているらしい。眼が視野に映らないという比喩も、ショーペンハウアーにほぼ同じものがある。違うのはその先で、ショーペンハウアーは身体の内側から意志に触れに行ったけど、論考はそこで黙る。REPLの中に入って触るか、外から見える範囲だけで止まるか、という違いだと思う。

ただ、これが論考の限界点だと思う。主体が世界の限界という一点に押し出されてしまうと、それ以上は何も語れない。他人がどうやって同じ言葉を使えているのか、みたいな話も扱えない。後期ウィトゲンシュタインが言語ゲームや規則の話に向かうのは、たぶんこの限界からなんだろう。

### 梯子：自分自身を型付けできない本

論考の最後で、ウィトゲンシュタインはすごいことを言う。この本の命題は、理解した人にとって最終的には無意味だとわかる。梯子を登りきったら、梯子は投げ捨てなきゃいけない。

なんでかというと、論考の命題の多くは、絵と世界がどう対応しているかや主体について語っていて、つまり示されるしかないものを語ってしまっているからだ。この本は、自分が定めた型検査器を自分では通らない仕様書なのだ。カントールの対角線以来の、自分自身を扱いきれないという問題が、本の構造そのものに出ているのが面白い。

ちなみに現実の仕様書だと、ECMAScriptの仕様書はESMetaみたいなツールで、仕様のアルゴリズム自体が型検査されている。論考と違って、自分で自分を検査するんじゃなく、一つ外側のツールでチェックしているわけだ。正しさの根拠を一段上に置くという点では、ラッセルやゲーデルの話と同じ構図になっている。じゃあそのツールは誰がチェックするのか、というところで、現実にはだいたい止まる。無限後退を、実用上は二段で打ち切っている感じだ。

### まとめ：健全だからこそ語りえぬものがある

ここまでをまとめると、論考の世界観は健全性の世界だと思う。書ける文は必ず世界の事実に対応していて、真か偽かが決まる。意味のない文は、そもそも書けない。型で言えば、通ったプログラムは絶対に変な動きをしない、健全な型システムだ。

けど、だからこそ語りえぬものが出てくる。言葉で世界を全部きっちり書ききれるということは、書けないものはきっぱり世界の外に押し出されるということだ。倫理も、生の意味も、主体も、この本自身の命題も、全部そっちに行く。語りえぬものは、健全さの裏側としてどうしても生まれてしまうものなのだ。

これは、普段使っている言語の性格の違いにも重なる気がする。Haskellは論考に近くて、健全さを大事にする代わりに、素直には書けないものがけっこうある。TypeScriptは逆で、`any` や型アサーションを使えばだいたい何でも書けるけど、その分健全さは手放している。Rustはその間で、基本は健全な世界を守りつつ、外に出るときは `unsafe` と書いて境界をはっきりさせる。どこまで書けるようにして、どこから先を外に押し出すか。言語ごとに、線の引き方が違うのだ。

## ゲーデル：自己言及が戻ってくる

1931年、ゲーデルは対角線をもう一度持ち出した。自然数の算術を含む十分強い体系では、「この文はこの体系で証明できない」という文が作れてしまう。

そこから二つの結論が出る。体系が無矛盾なら、真だけど証明できない文がある。そして体系は、自分自身の無矛盾性を自分で証明できない。

型理論で言うと、型システムの健全性は、いつもそれより強いメタ体系の中で証明される。そのメタ体系の健全性は、さらに外に依存する。体系は自分の正しさを自分では保証できない。ラッセルが型で塞いだはずの自己言及は、こうして別の形で戻ってきた。

これを論考と並べると面白い。論考では、言葉と世界がどう対応しているかは言葉の中では語れず、示されるだけだった。けどゲーデルは、文や証明に番号を振る（ゲーデル数）という仕掛けで、算術の言葉の中に、その言葉自身についての話を持ち込んでしまう。「この文は証明できない」という文は、まさに言葉が自分自身について語っている。論考が語れないとした領域に、ゲーデルは一部だけ踏み込んだわけだ。

それでも、全部は語りきれなかった。体系は自分の無矛盾性を自分では証明できず、そこはやっぱり外に残る。論考が「示されるしかない」と言った場所を、ゲーデルは定理として正確に測ってみせた、とも読める。ちなみにウィトゲンシュタイン自身は、ゲーデルの定理にかなり懐疑的だった。この話はあとでまた出てくる。

## 自己言及の塔

ゲーデルの話を踏まえると、こう思えてくる。世界を語るには、自分自身も語れる言語が要るんじゃないか。やっぱりLispなのか。コードとデータが同じ形をしていて、言語が自分自身を解釈できる。

けど、自分を語れることこそが、カントールから続く対角線論法の正体だ。チューリングの停止性問題もこれで、どんなプログラムについても止まるかどうかを判定するプログラムを作ろうとすると、それを自分自身に食わせたところで矛盾が出る。型システムは、この自分で自分を扱うことを禁じることで、矛盾を避けている。世界を語る者が自分自身も語ろうとすると、必ず穴が開く。

道は二つありそうだ。一つはループにとどまること。ホフスタッターは、自己言及のループから自己が立ち上がると考えた。もう一つは階層化。3-Lispという言語は、インタプリタを解釈するインタプリタが無限に積み重なる「反映の塔」を持つらしい。自分を語ることは許すけど、語る自分は常に一段上にいる、という発想だ。

この塔の哲学版が、西田幾多郎の自覚だ。西田はロイスの地図のパラドックス、つまりイギリスの中にイギリスの完全な地図を描くと無限に入れ子になる話を扱って、自己が自己に於て自己を写す構造を論じた。その入れ子を包む最終的な場所として、西田は絶対無を置く。けどここには、次に出てくる東浩紀の否定神学批判がそのまま刺さりそうだ。語れない一つの究極点を、結局立てているんじゃないか。

本当はこのあと、デリダと、さっき少し触れた後期ウィトゲンシュタインの話をしたい。けど、どっちもまだちゃんと読めていないので、読んだらまた別の記事で書こうと思う。

## 東浩紀の郵便的：一点か、散らばった穴か

ここまで、全部を扱おうとする体系は自分自身を扱いきれない、という構図をずっと見てきた。じゃあ、穴があることを前提に、どう語ればいいのか。ここからはその先の話を、Claudeとだらだら話した流れに沿って追ってみる。出発点は東浩紀の「郵便的」だ。

『存在論的、郵便的』の問いは、なんでデリダは70年代以降に変な書き方になったのか、というものだった。東の読みだと、前期の脱構築は「どんな体系にも語れない一点がある」と示すゲーデル的な論法だった。けどこの論法は、その不可能な一点を超越的な中心として祀り上げてしまう。東はこれを否定神学と呼んだ。

これは、この記事でずっと見てきた構図そのものだ。カントの物自体も、論考の語りえぬものも、体系の外に語れない一点を置いて、それを一番大事なものとして扱っている。東の否定神学批判は、そのままカントにも論考にも刺さる。

そこで東が持ち出すのが「郵便」だ。手紙は、ちゃんと宛先に届くとは限らない。でもそれは、どこか一つの大きな穴のせいじゃなく、配達のあちこちで小さな事故が起きているだけだ。

ポイントは、語れないものを一点にまとめるか、散らばったものとして見るか、の違いだと思う。一点にまとめると、それは神様みたいな特別なものになってしまう。でも散らばっているなら、それぞれは普通の小さな失敗で、その場その場で対処すればいい。

これ、ちょっとショーペンハウアーっぽい気もする。カントは物自体を経験の外の一点に置いたけど、ショーペンハウアーは、それが自分の身体の中にあって、欲望や苦しみとして日常のあちこちで感じられると言った。遠くの特別な一点じゃなく、身近にいつもある、という点では郵便に近い。ただショーペンハウアーの意志は、散らばって現れるけど、根っこはすべての裏にある一つの意志だ。郵便のほうは、その根っこの一つすら置かない。

## 穴の扱い方の螺旋：TSからRustへ

穴が散らばっているのを普通のこととして受け入れる、という郵便的な見方は、プログラミング言語の歴史にもそのまま重なる。言語は、穴の扱い方を螺旋状に進めてきた。

| 言語         | 穴の扱い方                                         |
| ------------ | -------------------------------------------------- |
| ML / Haskell | 健全であるべきという理想                           |
| TypeScript   | 現実に合わせて穴を許す。穴は散らばっている         |
| Rust         | 穴を `unsafe` で囲い込み、どこにあるかを宣言させる |

進歩の中身は、穴を受け入れること自体じゃない。穴がどこから入ってくるかを、はっきり書けるようになったことだと思う。

つまりプログラミング言語も、実は穴を完全に塞ごうとする努力はやめている。プログラミング言語はすごく現実的なもので、実際に動くものを作らなきゃいけない。だからこそ、穴をなくすより、穴とどう付き合うかの方向に進んだんだと思う。それが、語れない一点を祀り上げるのをやめて、散らばった穴を受け入れようとする哲学の方向と一緒なのが面白い。

ちなみにこの対立は、1939年にウィトゲンシュタインとチューリングがもうやっている。ケンブリッジでの数学の基礎についての講義で、チューリングは、矛盾を含む体系で計算したら橋が落ちる、と言った。ウィトゲンシュタインは、矛盾は見つかった場所で対処すればいい、と返した。穴を絶対に塞ごうとするか、穴と付き合うか。

ウィトゲンシュタインがゲーデルに懐疑的だったのも、同じところから来ていると思う。穴があること自体を否定していたわけじゃない。疑っていたのは、ゲーデルの結果を数学の基礎を揺るがす大事件として扱う態度のほうだ。穴を一点の深淵として祀り上げることに懐疑的だった、という意味では、郵便の話とも重なる。

## 確定せずに語る

穴と付き合うとして、意味がはっきりしないものを抱えたまま、どう語ればいいのか。ここで、ショーペンハウアーと前期ウィトゲンシュタインが対照的な答えになっている。

ショーペンハウアーは、世界の根にある意志を、概念できっちり定義しない。身体の内側から感じられるもの、音楽に一番よく現れるものとして、例と経験で語り続ける。ショーペンハウアーの章でLispにたとえたけど、これは型を先に決めずに、動かしながら確かめていく動的型付けのやり方に近い。意味を確定しなくても、語ることはできる。

前期ウィトゲンシュタインは逆だ。意味が確定しないものには、そもそも手を出さない。TypeScriptで言えば `unknown` で、何でも入るけど、中身を確かめるまでは何もさせてくれない。「語りえぬものには沈黙せよ」は、まさにこれだ。

その中間にあるのが、漸進的型付けという考え方だ。型が付いている部分と付いていない部分を、一つのプログラムの中に混ぜて書ける。TypeScriptも、JavaScriptに少しずつ型を足していけるという意味では、この発想の上にある。型付きの部分ではウィトゲンシュタインのようにきっちり語り、型なしの部分ではショーペンハウアーのように動かしながら語る。

どっちか一方を選ばなくてもいい。きっちり語れるところはきっちり語って、まだ語れないところは動かしながら確かめていく。現実のコードベースは、だいたいそうやってできている。

## 実行と一回性

動かしながら確かめる、と書いたけど、じゃあ現実における「実行」ってなんだろう。

プログラムと現実で決定的に違うのは、プログラムは何度でも実行し直せるけど、現実はできないことだ。現実は副作用だらけの一回きりの実行で、巻き戻しもテストもない。

それでも、一回性のほんの一部は型に乗る。Rustの所有権がそうだ。値を別の変数に渡したら、元の変数はもう使えない。

```rust
let s = String::from("hello");
let t = s;          // s の所有権が t に移る
println!("{}", s);  // コンパイルエラー：s はもう使えない
```

一度手放したものは、もう取り戻せない。ちなみに、これをもっと突き詰めた線形型という考え方もあって、ちょうど一回だけ使う資源を型で表せるらしい。Idris 2みたいに、それを依存型と組み合わせた言語もあるそうだ。

これまでの型は、値が何であるかは書けても、何回使えるかは書けなかった。でも現実のほとんどのものは一回きりだ。払ったお金は戻ってこないし、出した手紙も取り消せない。所有権や線形型は、そういう現実に近い一回性を型で書こうとしている。

じゃあ哲学の側は一回性をどう扱ってきたのか。面白いのはニーチェで、永劫回帰は、人生をプログラムとして見たらどうなるか、という発想に近い（気がする）。同じプログラムは何度でも、まったく同じように実行できる。じゃあこの人生が無限に再実行されるとしたら、それを望めるか。型が現実の一回性に近づこうとしているのに対して、ニーチェは一回きりの人生をあえて無限に繰り返せるものとして考えることで、その一回の重みを問うた。

自分が面白いと思っているのは、型システムの上では、「何度でも使える」と「一回しか使えない」が、雰囲気じゃなく規則として書き分けられることだ。だとしたら、ニーチェの問いも、比喩で言い換えるだけじゃなく、構造として扱えるんじゃないか。そうなったとき、世界とは何かという問いの見え方そのものが変わる（気がする）。まだ直感でしかないけど、ここは今後も考えていきたい。

## 空の空：ナーガールジュナと圏論

最後に、もう一度穴の話に戻りたい。ここまで、語れないものを一点として祀り上げるか、散らばったものとして付き合うか、という分かれ道を見てきた。けど、そもそも根っこになる一点をまったく置かずに語ることはできるのか。その手がかりになりそうなのが、ナーガールジュナだ。

『中論』の中心は、あらゆるものは自性を持たず、関係の中でだけ成り立つという縁起の主張だ。そして決定的なのが、空もまた空である、という一手。すべては空だと言うと、今度は空が究極の根拠になりかねない。ナーガールジュナはそれをはっきり拒む。語りえぬ一点を神聖化しない、という東の要求を2世紀にやっているのがすごい。さらに二諦の区別がある。世界の根っこには確定した中身がない、でも日常の約束事としての言葉はちゃんと働く。確定せずに語る、の章で書いた漸進的型付けの話と、かなり近い構図だと思う。

数学には圏論という分野があって、物の中身を見ずに、物と物の関係だけで全体を語るらしい。これがナーガールジュナの縁起にかなり似ている（気がする）。しかも、型と論理と圏論は同じ構造の三つの顔だ、という話（カリー＝ハワード＝ランベック対応）もあるらしい。だとしたら、型と仏教も意外と遠くないのかもしれない。ちゃんと読めていないので、ここは今後の宿題にしたい。

## おわりに：型でわかること、わからないこと

プログラミングの側から哲学を読めるんじゃないか、と思って始めたけど、やってみると、型で哲学がわかるというより、型で哲学のどこが構造で、どこが構造じゃないかが見えてくる、くらいが正しい気がする。

振り返ると、ずっと同じ話をしていた。カントールの対角線から始まって、全部を扱おうとする体系は自分自身を扱いきれない。ラッセルはそれを塞ぐために型を発明し、論考は健全さと引き換えに語りえぬものを世界の外に押し出し、ゲーデルはその穴が消せないことを示した。そこから先は、穴を一点として祀り上げるか、散らばったものとして付き合うか、という分かれ道だった。東浩紀の郵便も、TypeScriptやRustの穴の扱い方も、ナーガールジュナの空の空も、自分には同じ方向を向いているように見える。

そのうえで、一番わくわくしたのは、型理論のまわりで今起きていることだ。所有権や線形型は、値を何回使えるかを書こうとしている。エフェクトシステムは、その処理が外の世界に何をするのか、つまり副作用そのものを型で書こうとしているらしい。依存型になると、型の中に値そのものが入ってきて、かなり細かいことまで型で言えるようになるそうだ。どれも、型が現実の側に少しずつにじり寄っている感じがする。哲学がずっと比喩でしか語れなかったものが、型の上では構造として書けるようになりつつあるのかもしれない。そこから世界とは何かという問いの見え方がどう変わるのかは、まだ全然わからない。

### 「意味のない文は、そもそも書けない」は誤り

「まとめ：健全だからこそ語りえぬものがある」で、自分は「書ける文は必ず世界の事実に対応していて」「意味のない文は、そもそも書けない」と書いた。どちらも誤りだ。

まず、意味のある文が事実に対応している必要はない。「猫がマットの上にいる」が偽だったとしても、この文は意味を失わない。命題は現実の絵で（4.01）、絵が描いているのは、事態が成り立つか成り立たないかの可能性だからだ（2.201〜2.202）。現実と合っていれば真、合っていなければ偽になるけど、何を描いているかは、真か偽かとは関係なく決まっている（2.21〜2.22）。つまり、命題が対応する相手は「事実」ではなく「ありうる事態」だった。本文はここを混ぜていた。

次に、意味のない文は一種類じゃない。論考は二つに分けている。

- **無意義（sinnlos）**：トートロジー（いつでも真）と矛盾（いつでも偽）。「雨が降っているか、降っていないかだ」は何も語らない。けど、書ける。算術の0が何も増やさなくても算術の記号の正当な一部であるのと同じで、論理の記号法の正当な一部でもある（4.46〜4.4611）。
- **ナンセンス（unsinnig）**：文の部品のどれかに、意味を与えていない文。「ソクラテスは同一である」がそれで、「同一である」を性質を表す言葉として使う約束を誰もしていないので、文として成り立たない（5.4733）。

そのうえで、ナンセンスが書けないというのは、論考が考えた理想の記号法の中での話だ。現実の言語では書けてしまう。論考自身が、哲学について書かれた命題の大半は、偽なのではなくナンセンスだと言っている（4.003）。本文の「梯子」の節では、論考の命題自体が最後には無意味だとわかる、と書いておきながら、まとめでは意味のない文は書けないと言っていた。自分の記事の中で矛盾していた。

型で言い直すと、こうなる。

```ts
const x: true = true; // コンパイルは通るけど、何も言っていない
```

```haskell
x :: Int
x = undefined -- 型は通ったふりをしているけど、中身がない
```

前者が無意義（トートロジー）に近く、後者がナンセンスに近い、というのが今の自分の理解だ。ただ、後者はあくまでたとえで、かなりゆるい対応だと思ってほしい。

### 「Haskellは論考に近い」は言い過ぎ

ここは、次の節のゲーデルの訂正と同じ混同をしていた。型が通れば実行中に型の食い違いが起きないという「型安全性」と、型を命題として見たときに論理として矛盾していないかという「無矛盾性」は、別の話だ。

型安全性で言えば、Haskellはおおむね健全だ。ただ、`unsafeCoerce` や `unsafePerformIO` のような、型を迂回する抜け道がある。名前に `unsafe` と付けて危ない場所を目立たせるのは、Rustと同じ発想だ（Haskellのほうが先だけど）。ただRustの `unsafe` はキーワードで、コンパイラが境界を区切るのに対して、Haskellのは名前の約束にすぎない。

無矛盾性で言うと、Haskellはもっとはっきり外れる。`undefined` や無限ループは、どんな型の値としても書ける。カリー＝ハワード対応で、型を命題、プログラムをその証明として見ると、これは「どんな命題でも証明できてしまう」ということだ。論理として見れば矛盾している。

論考の理想言語に近いのは、定義した関数が止まるかを検査するLeanやAgdaのほうだ。この二つでも止まらない定義は書けるけど、Leanなら `partial`、Agdaならプラグマのような印を付けないと通らない。

同じ理由で、ブラウワーの節の「HaskellやLeanの型の世界は、この見方の上に立っている」も言い過ぎだった。Haskellは上のとおり、論理として見ると矛盾しているので、「証明はプログラム」の見方をそのままは当てはめられない。Leanの核は構成的だけど、標準で `Classical.choice` という公理があって、排中律も使える。

### 細かい訂正

- **論考の始まり**：「論考は論理空間から始まる」と書いたけど、冒頭は「世界は成り立っていることのすべてである」（1）で、始まりは世界のほうだ。
- **事実と事態**：論理空間の説明で「成り立つか成り立たないかの小さな事実」と書いたのは、用語としては「事態」が正しい。事実は、成り立っている事態のほうを指す（2）。
- **ゲーデルの節**：「型システムの健全性は、いつもそれより強いメタ体系の中で証明される」と書いたけど、型安全性（型が通ればおかしな動きをしない）と、論理体系としての無矛盾性を混ぜていた。単純な型システムの型安全性は、弱い体系で証明できる。第二不完全性定理が効くのは、算術を含むような強い型理論を論理として見たときの、無矛盾性のほうだ。
- **ラッセルの節**：還元公理が必要になったのは、型で階層を分けたせいじゃない。階（order）まで細かく分けた「分岐型理論」にしたからだ。階を分けない単純な型理論なら、還元公理はいらない。ちなみに無限公理は、単純な型理論でも必要になる。
- **カントのアンチノミー**：ラッセルのパラドックスと「ほとんど同じ形」と書いたのは言い過ぎだった。アンチノミーは、「世界は有限だ」と「世界は無限だ」のように、食い違う二つの主張がそれぞれ論証できてしまうものだ。原因は、経験の中でしか与えられない条件の連なりを、まるごと一つの対象のように扱ったことにある。ラッセルのパラドックスは、「自分自身を要素に含むか」という自己言及から、一つの定義の中で矛盾が出るものだ。仕組みは違う。「限界を越えると矛盾が出る点で似ている」くらいが正確だと思う。
