# アーキテクチャ解説

Void + Cloudflare（Workers・D1・R2）で動かす技術ブログの設計解説。「なぜこの構成か」を残すドキュメント。
判断の経緯（採用理由・却下した代替案・ハマりどころ）は `build-log.md`、作り直しの計画と現在地は
`void-cloudflare-rebuild.md`、バックアップは `backup.md`、ローカルの環境変数は `local-env.md`。

## 全体像

記事は管理画面（`/admin`）で書き、公開の操作で **D1（編集用の正）から R2（読者が見るスナップショット）へ書き出す**。
読者のリクエストは R2 だけを読み、ISR でキャッシュされる。

```
 管理画面 (/admin, 自分だけ)                     公開側 (読者)
 ┌──────────────────────────┐                  ┌─────────────────────────────┐
 │ エディタ → 自動保存       │                  │ /  /posts/<slug>  /tags/…    │
 │ プレビュー（同じパーサー）│                  │ /posts/<slug>.md  /og/<slug>.png │
 └────────────┬─────────────┘                  │ /feed.xml /sitemap.xml        │
              │ PUT（下書き）                    │ /search-index.json            │
              ▼                                 └──────────────┬──────────────┘
        ┌──────────┐   公開（検証→R2→D1→集計→ISR）            │ 読むのは R2 だけ
        │   D1     │ ───────────────────────────►  ┌─────────┐ │ （D1 には触れない）
        │ posts    │                              │   R2    │◄┘
        │ revisions│                              │published│
        │ tags …   │                              │uploads  │
        └──────────┘                              └─────────┘
```

## 設計の軸

### 1. 公開側は D1 を読まない

D1 は読み取り行数・書き込み行数での従量課金で、想定外のアクセス増で請求が跳ねる事故がありうる。そこで **D1 は
管理画面（認証済みの自分だけ）からのみ使い、公開側のアクセスでは一切クエリしない**。公開時に、公開側が必要とする
ものをすべて R2 に書き出しておく。

これは 2 つの方法で守っている。コードの上では、公開側の入口（`pages/**` の公開ページ、`routes/` の公開ルート、
`middleware/`）から import を辿って D1 に触れるモジュールに届かないことを `src/site/public-boundary.test.ts` が確かめる。
実行時には、`scripts/qa-preview.ts` が **D1 の全テーブルを消した状態でも公開側がすべて同じ結果で返る**ことを確かめる。

### 2. 重い処理は、リクエストごとではなく公開時に 1 回だけ

Workers は CPU 時間が短い（無料プランは 10ms。有料プランは既定 30 秒）。シンタックスハイライト（shiki）、
OG 画像（WASM 版 Takumi）、検索索引・feed・sitemap の組み立ては、公開の API の中で 1 回だけ行う。このため
本番は有料プランを前提にしている。

### 3. Workers で動くものだけを使う

ネイティブモジュール（NAPI）は Workers で動かない。旧構成の部品は次のように置き換えた。

| 旧                                         | 新                                                    |
| ------------------------------------------ | ----------------------------------------------------- |
| ox-content（Markdown パーサー、Rust/NAPI） | 自作の TypeScript のパーサー（`src/markdown/parse/`） |
| shiki（Oniguruma の WASM）                 | shiki + JavaScript の正規表現エンジン                 |
| takumi-js（OG 画像、ネイティブ）           | `@takumi-rs/wasm`                                     |
| ビルド時に生成する feed・sitemap・検索索引 | 公開時に生成して R2 に置く                            |

## データ

### D1（`db/schema.ts`。マイグレーションは `db/migrations/`）

| テーブル                                        | 役割                                                                                                                                                                              |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `posts`                                         | **公開中の版**。管理画面の一覧はここだけを軽く引く（本文を引かない）。一度も公開していない記事は `publishedRevisionId` が NULL                                                    |
| `post_revisions`                                | **編集中の下書きと履歴**。`draft`（記事ごとに 1 行。自動保存が上書き）、`snapshot`（5 分以上空いたときだけ追加。上限 50 件で古い順に削除）、`published`（公開時の版。別枠で保持） |
| `tags` / `post_tags`                            | タグの正規化テーブル。`post_tags` は公開中の版に対するもの。URL 用のスラッグ（`transliteration`）は現行と同じ                                                                     |
| `assets`                                        | R2 にアップロードした画像の管理表                                                                                                                                                 |
| `user` / `session` / `account` / `verification` | Better Auth のテーブル（Void が生成。セッションは D1 に置く）                                                                                                                     |

すべてのクエリは索引に乗せ、一覧は列を絞ってページングする。

### R2

| キー                                                       | 中身                                                                                          |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `published/posts/<slug>.json`                              | 記事のスナップショット（frontmatter・パース済みの AST・目次・コードのハイライト済みトークン） |
| `published/posts/<slug>.md`                                | 原文（frontmatter 付き）。`/posts/<slug>.md` で配信し、バックアップを兼ねる                   |
| `published/og/<slug>.png`                                  | OG 画像（1200×630）                                                                           |
| `published/index.json`                                     | 記事一覧とタグの集計（トップ・タグ一覧・タグ詳細が読む）                                      |
| `published/feed.xml` / `sitemap.xml` / `search-index.json` | 公開のたびに、公開中の全記事から作り直す                                                      |
| `uploads/<年>/<月>/<ランダム>.<拡張子>`                    | アップロードした画像（`/uploads/…` で配信）                                                   |

下書きは R2 の公開側には書き出さないので、`draft` や未公開の記事は、どの配信にも出ない。

## 公開操作（`src/site/publish.ts`）

公開は 1 つの関数に集約している。順序は **検証 → R2（記事・`.md`・OG）→ D1（公開版の履歴・`posts`・`post_tags`）→ 集計物の
作り直し → ISR の無効化**。

- **読者が見るのは R2** なので、R2 を先に書く（逆順だと、管理画面では公開済みなのに読者には届いていない状態になる）。
- **検証に失敗したら何も書かない**（`error` の診断が 1 つでもあれば 422）。
- **冪等**: R2 は上書き、公開版の履歴は内容が同じなら再利用、集計物は毎回作り直す。どこで失敗しても、同じ操作を
  もう一度実行すれば収束する。
- OG 画像と ISR の無効化の失敗は、記事の公開を止めず、結果に警告として載せる（`ogError` / `revalidateError`）。
  OG は、最初のアクセスで描画して補う（`middleware/04.og.ts`）。
- 取り下げは R2 を先に消す。タグ名の一括変更は、公開中の版の内容のまま公開し直す。全記事の作り直し（`republishAll`）は、
  パーサーを変えたあとや復元のあとに使う。
- ISR の TTL は長く（30 日）し、公開・更新・削除の直後に、関連するパス（記事・トップ・タグ・feed・sitemap・検索索引）を
  `revalidate({ paths })` で無効化する。

## 公開側

Void の Pages mode（`pages/`）と、島（アイランド）による部分ハイドレーション。

- **ページ**: `pages/` のトップ・記事・タグ・About・404。ローダー（`*.server.ts`）は `src/site/read.ts` 経由で R2 を読む。
  存在しないものは `x-not-found` ヘッダーを付けて返し、`middleware/02.not-found.ts` が 404 に書き換える
  （ページのローダーは、ステータスを変えられないため）。
- **ルート**（`routes/`）: `feed.xml`・`sitemap.xml`・`search-index.json`（R2 の同名のものを返す）、`/uploads/*`（画像。
  キーの形を検証し、`nosniff` と長期キャッシュを付ける）。
- **ミドルウェア**（`middleware/`）: 共有データ、404、`/posts/<slug>.md`、`/og/<slug>.png`。後ろの 2 つは、ファイル名の途中に
  パラメータを置くルートを Void が展開しないので、ミドルウェアで処理する。
- **URL**: 現行の体系（`/posts/<slug>`、`/tags/<tag>`）を維持する。`.html` や末尾スラッシュの揺れは、`void.config.ts` の
  `routing.redirects` で 301（ワーカーの前で評価される）。
- **検索**: ブラウザで索引（`/search-index.json`）を読み込んで、部分一致で探す（`docs/search.md`）。

### 島（アイランド）の決まり

島は、**ページのファイルで `with { island: "load" | "visible" }` を付けて import した、default export のコンポーネント**だけが
動く。`#` のサブパスではなく相対パスで import する。レイアウトの中の島は、描画されるだけで動かない。このため、ヘッダー・
本文・フッターの枠（`src/components/Page.tsx`）は各ページが使い、検索欄は各ページのファイルで島にして渡す。

## Markdown

### 自作のパーサー（`src/markdown/parse/`）

純 TypeScript・依存ゼロで、**サーバー（公開時の検証）とブラウザ（エディタのプレビュー）の両方で同じコード**が動く。例外を
投げず、書きかけの入力でも必ず AST と診断を返す。ブロック（コンテナの再帰）と、インライン（CommonMark の delimiter run
による強調）の 2 段で、ノードに位置を持たせる。診断は `{ severity, ruleId, message, from, to, line, column }` で、
frontmatter・URL スキーム・lint（重複見出し・連続空行・繰り返し語など）を担う。

### 描画（`src/markdown/components.tsx`）

mdast を `type` で分岐して React 要素にする（判別可能ユニオン）。コードのハイライトは描画から切り離してあり
（`highlight.ts`）、公開時に AST の `code.highlight` に埋める。描画側は埋まったトークンを並べるだけの同期の処理なので、
読者のリクエストでは shiki が動かず、ブラウザのプレビューでも同じ関数を呼べる。

## 管理画面（`/admin`）

- **認証**（`auth.ts`）: GitHub ログインだけ。自分の GitHub の**数値のユーザー ID**（`ADMIN_GITHUB_ID`）と一致する
  アカウントだけを通す。アカウント作成のフックと、認可での D1 の確認の二重で守る。スクリプト用に Bearer トークン
  （`ADMIN_API_TOKEN`）、開発サーバーだけの認可の省略（`ADMIN_DEV_BYPASS`）もある。
- **管理 API**（`routes/api/admin/`）: 記事の一覧・詳細・保存・削除・公開・取り下げ、履歴と巻き戻し、画像アップロード、
  タグの一覧と一括変更、書き出し・復元・全記事の作り直し。
- **エディタ**（`src/admin/`）: CodeMirror 6。入力のたびに公開時と同じ検証を流し、プレビューにエラー一覧（行番号付き、
  クリックで該当行へジャンプ）とエディタ内の印を出す。エラーがあると公開できない。2 秒で自動保存、未保存のまま離れると確認。
- **履歴**: 差分（行単位）の確認と巻き戻し。巻き戻す前の下書きは履歴に残る。公開中の版は、公開し直すまで変わらない。
- **画像**: ペースト / ドロップ → ブラウザで WebP に変換 → R2。サーバーは中身（マジックナンバー）で種類を判定し、SVG は断る。
- **タグ**: 既存タグを候補に出し、URL が同じで表記だけ違うものを警告する。名前の一括変更・統合は `/admin/tags`。

```

├─ admin/            管理画面の部品（エディタ・プレビュー・履歴・タグ・画像）

design/              デザインの試作
```

## 規約

- **import は subpath imports**（`package.json` の `"#*": "./src/*"`。拡張子は `.js`）。ただし島は相対パスで import する。
- **コメントは日本語**。コードだけを読む人に通じる、自己完結した内容にする。
- **TypeScript はネイティブ版（`tsgo`）に一本化**。
- push 前のフック（`lefthook.yml`）が整形・lint・型・単体テスト・ビルドを回す。**ビルドは `URLPattern` を使うので、
  Node 22 以下では落ちる**（Node 24 を使う）。
